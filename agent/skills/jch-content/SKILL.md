# Update JCH content

Read JCH's own instructions and existing content/deployment recipes. Identify
whether the request concerns production content or code before changing it.
Use the current CMS/API for content; a local-only change does not update the
public website. The Liga table already has a GitHub workflow: reuse it.

Read the original report/email and its attachments. Preserve exact wording
when requested; do not invent results, people, dates or photo permissions.
Keep the site's branding and match existing content structure.

Perform the authorized update with the correct identity, then verify the live
page and media. Report the URL and any concrete remaining blocker. Code fixes
follow the repo's commit/push/deployment permissions; content authorization is
not a blanket permission to publish unrelated code.
