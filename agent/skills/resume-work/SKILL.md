# Resume work

Read the latest relevant T3 messages and task status first, then inspect the
actual branch/worktree, diff, owned processes and last verification evidence.
Keep fixtures and checkpoints in ignored project state when they must survive
a restart or later review; recover owned jobs before starting replacements.
Search only the named project/topic; expand history when a decision needs it.
Treat old orchestration messages as history, not renewed authorization.

State the resume point and keep one current acceptance list in the thread:
completed, pending, blocked. Incorporate Mathis's steering without discarding
the original objective. Continue from the last verified point; do not repeat
completed exploration or create a competing coordinator.

For cross-host work, follow the
[environment handoff workflow](../../workflows/environment.md#handoff-to-the-right-computer):
prefer the correct host's existing owner or a native thread there over elaborate
routes from the wrong machine. For any cross-host/harness handoff, send the
objective, scope and acceptance criteria, exact paths/branch/revision, decisions,
pending work, and evidence. Identify source-only dirty changes and verify the
destination context and ownership; do not assume another checkout has those edits.
Use the existing project record, never a parallel progress ledger. Verify
inherited claims before reporting done.
